## EXPLICIT — Report 1 FE-05–FE-06, FE-21, FE-26, FE-33–FE-34, FE-45–FE-46, FE-52–FE-53

Members view upcoming Masses, ceremonies, performances, and rehearsal schedules (FE-05) and respond with Confirm attendance, Decline attendance, or Unsure (FE-06). The Choir Director creates rehearsal schedules for each event (FE-26), sends confirmation requests (FE-33), views status in real time (FE-34), takes attendance at rehearsals or service-preparation sessions (FE-45), and tracks practice progress and attendance (FE-46). ## BE contract (verified `a6af23e`, re-checked `d550665`)

- **Participation** (`EventParticipationService.cs`): requests go to chosen active members (or to every active member not yet asked, when no ids are sent) for a **published**, not cancelled event that has not started; status `Invited` → `Confirmed` / `Declined` / `Unsure` (`ParticipationStatus.cs`). Each member is asked **once** per event (`EVENT_PARTICIPATION_ALREADY_REQUESTED`); there is no resend or reminder. A member answers **once** (`EVENT_PARTICIPATION_ALREADY_RESPONDED`), with an optional note, only while active and before the event starts (`EVENT_PARTICIPATION_CLOSED`). Since D8 only the lead choir's director sends requests (`CHOIR_NOT_LEAD`, `:34`) and only members of the serving choirs can be invited (`:244-256`). Since `088f30a` (2026-11-13) the Parish Priest sends them too (`EventParticipationsController.cs:17-19`); the Web does it right after publishing, without `memberIds`, so every active member of the serving choirs is asked, and the director's page then asks only those added later.
- **Confirm all** (`ef2277f`): the Choir Director of the lead choir can confirm every still `Invited` request of an event in one call (`POST api/event-participations/confirm-all?eventId=`, `EventParticipationsController.cs:31-37`, `EventParticipationService.cs:133-165`); `Declined` and `Unsure` stay, nobody is notified, and the event may already be past (made for demos). A cancelled event answers `LITURGICAL_EVENT_CANCELLED`.
- **Rehearsal** (`RehearsalService.cs`): has a start and end time (end after start); the event, the place (catalog) and the songs are **optional**; an event, when given, must not be cancelled. No status field. A rehearsal that has ended cannot be edited (`REHEARSAL_ALREADY_PASSED`); one with recorded attendance cannot be deleted (`REHEARSAL_HAS_ATTENDANCE`); a rehearsal at the same place with an overlapping time is refused (`REHEARSAL_TIME_CONFLICT`). Each song of a rehearsal can carry a note (≤ 500, `UpdateRehearsalSongRequest.cs:7`, `UpdateRehearsalSongRequestValidator.cs:12`), e.g. what to work on; the Web sends and shows it since #254. One rehearsal is read by id through `GET api/schedule/rehearsals/{id}` (any signed-in role, a director sees the choirs they lead; `ScheduleController.cs:32-34`), which the Web's practice room uses when opened by its link. **Recordings** (`90af733`, B43): the Choir Director records takes of a rehearsal of their choirs, for one song or the whole session, and deletes them; members of the rehearsal's choir listen on mobile (`RehearsalsController.cs:83-109`; `.webm`, `.ogg`, `.m4a`, `.mp3`, `.wav`, ≤ 20 MB). Deleting the rehearsal deletes its recordings. Editing, and deleting a rehearsal that has not ended, notify the rehearsal's choir (`NotificationType.RehearsalChanged`, `RehearsalService.cs:221-235`); creating one notifies nobody.
- **Rehearsal choir** (D8, `718696c`): a new rehearsal needs `choirId`, a choir the director leads (`CHOIR_NOT_FOUND`), active (`CHOIR_INACTIVE`) and, when an event is given, serving it (`CHOIR_NOT_SERVING_EVENT`) (`ChoirScopeService.cs:34-57`). A Choir Director lists and edits only rehearsals of their choirs; attendance is recorded only for members of the rehearsal's choir (`RehearsalAttendanceService.cs:52-57`).
- **Attendance** (`RehearsalAttendanceService.cs`): values `Present`, `Absent`, `Late`, `Excused` (`AttendanceStatus.cs`); recorded once per member per rehearsal, for active members only, and only from a configurable number of minutes before the rehearsal starts (system setting; `REHEARSAL_NOT_STARTED` before that). The Admin can switch that check off with `Rehearsal.AttendanceStartCheckEnabled` (default on, `32e8185`, `RehearsalAttendanceService.cs:44-50`); the Choir Director cannot read the setting (B49).
- Per-member reports count attendance, participation confirmation and assignment completion (`ReportType.RehearsalAttendance`, `Participation`, `AssignmentCompletion`); the Admin and the Choir Director read and export them, optionally for one choir (`choirId`) (`446f429`, `ReportsController.cs:44-70`).

## Owner decisions still standing (BE silent)

- A service-preparation session is created as a rehearsal; no recurrence.
- Confirmation round: the Director chooses recipients (all active members by default). A later send reaches only members not asked yet; resending to non-responders is not possible in the BE.
- No reminders for rehearsals and no attendance at the Mass itself.
- Report metrics (3.1): attendance rate = sessions present ÷ practice sessions of one event; confirmation rate = members who confirmed ÷ members sent the request.
