# API wire conventions (Web and Harmonia-BE)

Verified against BE `main@d394db4` on 2026-10-31 (a MIDI file the BE cannot render answers `422 MIDI_*`; a material may have no file, `fileName` and `fileUrl` `null`); at `43dfe31` on 2026-10-26 (D8 choir rules: `CHOIR_NOT_LEAD` is a `403` with a body, `CHOIR_LEAD_INVALID` arrives inside `VALIDATION_FAILED`; `GET /api/system-settings/public` works without a session; contract changes are listed in the BE `doc/api-changelog.md`); at `42e604e` on 2026-10-25 (the Choir Director reads the three per-member reports and exports them); at `a6af23e` on 2026-10-20 (publish answers `LITURGICAL_EVENT_TYPE_REQUIRED` and `LITURGICAL_EVENT_SEASON_REQUIRED` as plain 400 codes, not inside `VALIDATION_FAILED`); earlier at `5aaacb0` on 2026-10-18 (times back to UTC, tbd-backlog B19). Re-check a detail in the BE code before relying on it.

- **Errors:** BE returns `{ code, message, errors?: Record<field, string[]> }`; field errors are codes. Show text by `code` from one table under `src/lib/api`, never the BE `message`. Unknown code: generic text, keep the code in logs. A `403` from `[Authorize]` and a routing `404` have an empty body, so branch on status; a `403` from a service rule carries its code (e.g. `CHOIR_NOT_LEAD`, `ErrorStatusMap.cs:198`). A rule checked by a validator arrives as a field code inside `400 VALIDATION_FAILED` (e.g. `CHOIR_LEAD_INVALID` under `leadChoirId`, `UpdateEventChoirsRequestValidator.cs`), so look for a code in both places.
- **Enums:** BE sends PascalCase names. Keep one mapper per feature between BE names and Web unions, send names (not numbers), and compare only after mapping.
- **Ids and dates:** ids are `Guid` strings. `DateTime` (`createdAt`, `publishedAt`, `accessTokenExpiresAt`, `startTime`…) is UTC ISO-8601 with `Z` (BE marks database values as UTC, `HarmoniaDbContext.cs:111`; `doc/api.md:9-15`); read it through the shared helper `parseUtc` (`src/lib/api/dates.ts`) and send `DateTime` with `Z` or an offset. `DateOnly` (`yyyy-MM-dd`) and `TimeOnly` (`HH:mm:ss`), e.g. `eventDate`, `time`, `dateOfBirth`, are calendar values in Vietnam: no time zone, never parse them with `new Date()`. "Today" on the BE is Vietnam time (UTC+7).
- **Success:** `200` with a body or `204` without one; never parse a body on `204`.
- **Paging:** `pageNumber` and `pageSize` (clamped: default 20, max 100) with a `PagedList` envelope. Do not page locally over a full list.
- **File download:** a file answer (e.g. `GET /api/reports/export`) goes through `apiDownload` (`src/lib/api/client.ts`), which keeps the body as a Blob and still reads a JSON error. The BE does not expose `Content-Disposition` to CORS, so the Web names the saved file.
- **File upload:** `multipart/form-data`. `apiRequest` must not force `Content-Type: application/json` for `FormData`; let the browser set the boundary. Read the controller for part names, required fields, extension whitelist and size limit. A refused file answers `400` (type, missing file), `413` (size) or, for content the BE cannot process, `422` (`MIDI_*`). File URLs are signed and expire; do not store them; a material without a file (typed lyrics) has `fileUrl: null`.
- **Tokens:** the session lives in `localStorage` through `src/lib/auth/session.ts` (owner decision 2026-10-03). Never log tokens. Refresh tokens rotate: always store the new one.
- **Password change required:** an account created by an Admin logs in with `user.isPasswordChangeRequired = true`; until it changes the password, every authenticated endpoint except logout, logout-all, change-password and `GET/PUT /api/auth/me` answers `403 AUTH_PASSWORD_CHANGE_REQUIRED` (`PasswordChangeRequiredFilter.cs:14-27`, `doc/api.md:106-110`). Send such a user to change the password instead of treating it as a permission error.
- **Public reads:** `GET /api/system-settings/public` answers without a session (`Parish.Name`, `Choir.Name`, `Contact.Email`; `SystemSettingsController.cs:24-29`), so the landing and sign-in pages may call it before login. Every other endpoint needs a session.
- **Contract changes:** the BE lists them by date in `doc/api-changelog.md` and marks breaking ones **[Phá vỡ]**; read it after each BE pull.
- **Route guards:** derive from `Session.user.roleName`. BE authorization is authoritative; hiding UI is only UX.
- **Stale stubs:** when BE ships an endpoint, remove that feature's fixture branch and `ApiContractMissingError` (decision 0002, section 3).
